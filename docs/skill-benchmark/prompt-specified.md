```
Build a multi-service event-driven app using tiko-di
(Maven Central: io.github.tomas-samek:tiko-*:0.1.0; includes
tiko-archetype for scaffolding).

Services
- service-purchases: consumes Kafka topic `purchases`
  payload { customerId, productId, timestamp }
- service-products:  consumes Kafka topic `products`
  payload { productId, name } — reference data, upsert
- service-users:     consumes Kafka topic `users`
  payload { customerId, name, email } — reference data, upsert
- service-prices:    consumes Kafka topic `prices`
  payload { productId, price } — reference data, upsert (latest wins)

Behavior
- services 2-4 persist their reference data in H2 (embedded, schema at
  startup).
- on every message service-purchases consumes, look up the product,
  the user, and the current price from H2, build a notification
  { customerName, productName, price, timestamp }, and publish it to
  Kafka topic `notifications`.
- if any reference row is missing at lookup time, log and skip the
  notification (no buffering, no retry — PoC).

Scope
- PoC. Schema and validation minimal. No auth, no metrics.
- Use the tiko archetype to scaffold. If you have access to the
  tiko-build skill, use it.

Done
- `mvn verify` green.
- one integration test publishes the four reference messages and one
  purchase, and asserts a single well-formed notification arrives on
  `notifications`.
```
